# hikes 微信小程序（Taro）

本目录按 `DEVICE_HANDOFF.md` 的小程序实施细则采用 Taro 3 + React + TypeScript。现有 H5 继续保留，小程序通过现有 HTTPS API 访问业务数据。

## 开发

```sh
npm install
npm run typecheck
npm run dev:weapp
```

默认 API 根地址为 `https://www.fotowa.fun/api`。如需切换环境，设置 `TARO_APP_API_BASE_URL` 后重新构建。该变量在构建期注入，修改后必须重新构建，再用微信开发者工具上传。请确认 `/health`、`/routes` 与 `/openapi.json` 都由 FastAPI 响应，再把 HTTPS 域名登记为微信 request 合法域名。用微信开发者工具打开本目录；项目已配置 AppID。

底部入口为山头、路书、首页、留言版、我；扫码从首页按钮进入。线路列表来自线上 API，连接失败时展示仓库的 157 条只读线路资料。线上山头点位当前缺名称，山头列表展示仓库收录的 100 座有名称的山峰资料；打卡、留言和个人记录只使用服务端数据。

## 已实现页面

- 首页：真实路线列表、扫码入口、近期留言、游客/账号到访凭证；每次回到首页刷新，加载失败时可点击重试。
- 路书列表/详情：接 `/api/routes` 与 `/api/routes/{slug}`，显示线路长度、爬升、参考用时、轨迹地图、难度适用的分段和山顶。
- 路书页顶部「机场信息牌」：每 3 秒翻牌换一条线路（`components/RecommendedBoard`），手指按住时暂停，翻牌那一刻才换内容，所以看到的线路和点进去的线路始终一致；网页版同名交互在 `app/js/app.js` 的 `hf-flip`。
- 路书详情坡度图：`components/SlopeChart` + `services/slope.ts`，与网页版 `apiProfileSVG`／`slopeBands` 同一套口径（±0.4 km 滑动窗口估坡度、≤15% 缓 / 15–25% 中 / >25% 陡、碎段按 1.5% 与 0.5 km 合并）。小程序不能内联 SVG，所以画成一根根竖条（纵轴海拔、颜色 = 该段坡度），下面接坡度分段清单。
- 排序口径：山头与路书列表按**互联网热度档**降序（`mountains.heat_tier`：极热 > 热门 > 较热 > 小众），再按本周打卡量；没有资料的山头/线路 `heatTier` 为空、排在后面，不插队。线路本身没有热度字段，热度取自线路峰点 1.5 km 内最近的有资料山头。
- 扫码/点位：`wx.scanCode` 识别现有 `/p/{code}` 短链或点位编号；匿名读取点位与山顶留言；游客 `POST /api/guest` 和 `POST /api/guest/visit`；显示到访序号和时间。
- 游客纪念：按 API 保存私人纪念及未公开留言草稿；公开留言需账号并在发布前明确确认。
- 微信账号：`wx.login()` code 交给后端 `/api/auth/wechat` 换 JWT；服务端合并游客打卡和草稿，登录后在多设备读取账号记录，登录前的点位发布流程会回到原点位。
- 山头维护说明：按无人维护/他人维护/本人维护呈现职责和贡献方式；已匹配服务端山头编号时可填写原因与维护计划，提交正式维护申请。
- 消息：登录后读取留言提醒和维护通知，可将未读消息标记已读；请求失败显示重试入口。
- 岔路与路段：各有独立资料页，分别读取点位或路书详情与对应留言；到访和发布继续进入现有点位／路书流程。
- 我的：已登录时接到访、想去列表，并提供隐私政策、用户协议、留言规范和删除账号入口。
- 第五周质量项：调用微信隐私授权流程；账号注销页要求重新验证当前微信身份，服务端比较 OpenID 后删除个人数据并匿名化保留内容；应用打开、扫码入口、点位浏览、到访和留言事件只上报白名单字段，不传点位编号、留言正文、令牌、精确位置或微信身份；遇到过期 JWT 清除本地登录态，到访请求保留幂等键以安全重试。
- 发布构建不包含开发登录入口；服务端 `/api/auth/dev-login` 仅在显式设置 `ALLOW_DEV_LOGIN=1` 时开放，生产部署不得设置该值。

## 联调配置与后续事项

- 后端需要配置 `WECHAT_APP_ID` 和 `WECHAT_APP_SECRET`；本地 Docker Compose 从 `server/.env` 读取，部署环境在服务器变量管理中配置。AppSecret 不得写进小程序配置。
- 登录请求通过 `X-Guest-Token` 头合并当前设备记录；账号登录后，打卡与草稿改走 JWT 保护的账号接口。
- 游客可保存私人纪念和公开留言草稿；游客不能创建公开留言。
- 首页近期内容 API 已存在；山头维护申请已接 `/api/king-applications`。本地目录中尚未匹配到线上山头编号的条目不能提交申请。山头协作与维护待办尚未接入小程序。
- 后端山头点位详情按点位 code 获取；若需要直接读取 mountainId 的独立详情，当前尚无已核实接口。

## 发布前质量门

- 当前 `dist/` 构建产物总大小约 0.38 MB；发布前需在微信开发者工具检查主包与分包大小，并保留空间给后续页面和资源。
- 已由静态构建覆盖微信小程序目标；仍须使用真实 AppID、已配置 HTTPS 合法域名及真实服务器做微信开发者工具联调。
- `npm test` 目前覆盖岔路卡片与服务端 `PointBrief` 字段映射；尚未覆盖页面交互、登录和扫码。`npm run typecheck` 与 `npm run build:weapp` 分别检查类型和构建。
- 真机回归清单：iOS/Android 扫码、手动输入、游客与账号到访、断网/弱网恢复、过期 Token、重复打卡、隐私授权同意/拒绝、账号注销成功/身份不匹配。此清单需要真实设备与账号，不能由本地构建替代。
