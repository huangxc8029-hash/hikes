# 权限、维护人激励与广告 · 设计提案

> 2026-10-13。**产品方案仍待冻结；权限已有部分实现。** 用户已确认的定位及广告规则以 [PRODUCT.md](PRODUCT.md) 为准；研究依据见 [USER_RESEARCH.md](USER_RESEARCH.md)。本文件提供可评审的完整方案，不替代当前 API 契约。

当前已实现：山头管理身份统一由 `mountain_members`（`owner|member` + `active|left|removed`）判定，同一山头只有一位在任负责人；申请先落私有记录，平台审核通过后才创建新山头、点位、短链、留言板并授予身份。旧 `claims`、直接建点与旧协作审核接口已停用（410 `UPGRADE_REQUIRED`），不能再绕过审核授权。负责人可组建山寨；成员加入必须经过负责人意见与平台最终审核，负责人意见本身不授权。退出、移除、移交和平台接管后权限立即失效，历史留言、二维码与打卡保留。

新增实现（迁移 `0019_email_and_platform_roles`）：密码注册要求邮箱并先进入待验证状态；邮箱确认前不签发登录令牌、不允许登录，游客记录只在验证成功后合并。邮件使用 SMTP 环境变量配置，验证 token 数据库存哈希且 30 分钟过期；接口 `POST /api/auth/resend-verification` 支持安全重发。已有账号在迁移时按历史行为视为已验证，避免上线后锁号。

平台角色管理入口为 `/app/platform-admin.html`，仅 `platform_admin` 能访问其 API。首次部署需由数据库管理员在可信账号上执行一次：

```sql
INSERT INTO system_roles (user_id, role)
VALUES (:trusted_user_id, 'platform_admin')
ON CONFLICT (user_id, role) DO NOTHING;
```

页面可检索账号并授予／撤销广告、地理资料、协作申请、留言申诉审核角色；每次变更要求理由并写入 `platform_role_audit_logs`。该页面不能授予或撤销 `platform_admin`，防止通过普通操作扩散最高权限。山头负责人和版主仍通过申请审核获得特定山头范围内的权限。

点位修改限本山头负责人；广告审核／首屏提升限 `system_roles.role='ad_reviewer'`，且不能自审或提升自己的广告；同一山顶板仅展示一个获准素材，新素材获批后替换旧版本。维护人可保存草稿、修改驳回版本并重提。审核员由数据库管理员明确授予，注册和维护人认领均不会自动取得该角色：

```sql
INSERT INTO system_roles (user_id, role) VALUES (:reviewer_user_id, 'ad_reviewer');
```

山峰身份人工核对由独立的 `place_curator` 角色执行；同一账号可被明确授予两个角色，但维护人资格不会自动成为审核员：

```sql
INSERT INTO system_roles (user_id, role) VALUES (:curator_user_id, 'place_curator');
```

当前已实现山顶板协作者申请、平台审核与撤销：获批者仅可处理本板留言，不能编辑点位或提交广告；审核员由数据库管理员明确授予 `collaboration_reviewer`，申请人与审核员不能是同一账号。维护操作审计以 `022_maintenance_audit.sql` 为准：点位编辑、隐藏他人留言、协作审批/撤销、广告审核/首屏调整与操作本身写入同一事务；记录操作者、资源、前后状态、理由和时间，不保存密码/令牌。隐藏他人留言须给理由，作者隐藏自己的内容不强制理由。`023_comment_appeals.sql` 增加原作者申诉与独立 `content_reviewer` 复核：每次隐藏最多一份申诉，审核员不能是原作者或隐藏执行人；恢复/驳回及理由留痕，恢复后再次隐藏才可再次申诉。当前未实现：广告投诉申诉、三类板统一的广告关联。不得把本轮权限补丁当成整套提案已验收。

## 1. 三条设计原则

1. **看现场信息不设注册墙。** 游客能阅读指路、路况、留言并打卡；先得到价值，再决定是否保留和参与。
2. **注册解锁连续关系。** 跨设备保存、私人记录、公开留言、关注及回复。会员不是“更有资格获得指路的人”。
3. **管理权限来自明确责任。** 称号、贡献荣誉、资源维护范围、广告提交资格分开；不靠打卡数自动取得管理权。

## 2. 权限矩阵

“协作者”是有范围的维护分工，不必做成新的用户等级。所有维护人同时拥有普通注册能力。

| 能力 | 游客 | 注册用户 | 本板协作者（授权范围内） | 本板维护人 | 平台运营／审核 |
| --- | --- | --- | --- | --- | --- |
| 看线路、三类板、最近路况和广告 | 可 | 可 | 可 | 可 | 可 |
| 打卡、查看本次凭证 | 可 | 可 | 可 | 可 | 可 |
| 跨设备保存、私人记录、关注及消息 | 注册后 | 可 | 可 | 可 | 可 |
| 公开留言、回复、提交路况或名称纠错 | 注册后，保留草稿 | 可，待核验信息有标识 | 可 | 可 | 可 |
| 提交举报／错误线索 | 可受限提交，不直接公开 | 可 | 可 | 可 | 处置 |
| 申请具体留言板的维护任务 | 注册后 | 可 | 可 | 可申请其他范围 | 审批 |
| 下载正式布设物料、登记巡查 | 不可 | 可预览；正式操作需授权 | 经授权可 | 可，仅本板关联点位 | 可 |
| 核验路况、提出名称／难度变更 | 不可 | 可提交建议 | 经授权可 | 可，仅本板 | 复核／发布争议变更 |
| 置顶、隐藏违规留言 | 不可 | 仅自己的内容按规则处理 | 经授权可，须理由 | 可，须理由；不硬删除他人内容 | 可审计、撤销 |
| 邀请协作者、交接维护关系 | 不可 | 不可 | 不可 | 提交申请，按规则生效 | 审批／撤销 |
| 上传本板广告草稿、提交审核 | 不可 | 不可 | 默认不可，可授权起草 | 可 | 可处理 |
| 审批、提升广告到首屏 | 不可 | 不可 | 不可 | 不可，包括自己的广告 | 具审核权限且无利益冲突者可 |
| 合并地理对象、全站封禁、跨板管理 | 不可 | 不可 | 不可 | 不可 | 指定权限可 |

游客举报为非公开输入，需频率限制和审核，不改变“公开留言需注册”的约定。用户可使用昵称；注册不意味着身份已实名核验，更不意味着内容可信。账户与广告相关投诉均有平台申诉入口。

## 3. 从扫码到注册：三个自然时机

| 时机 | 引导内容示例 | 保证 |
| --- | --- | --- |
| 打卡成功后主动保存 | “把这次登顶收进你的山峰记录，换手机也能找到。” | 当前打卡已成功；不注册仍能看凭证；说明游客存储边界 |
| 写好公开留言后提交 | “用一个昵称留下这句话，收到回复时再来看。” | 先保留草稿，注册后回到原板完成提交；支持取消 |
| 主动关注路况／地点 | “保存这座山，下次出发前看看有什么变化。” | 更新通知自选；不默认开启营销消息 |

不要求游客先填真实姓名、详细资料或上传 GPX。所有研究中的文案均为待测试示例。新用户不被强制引导成为维护人；已有价值的浏览和私人记录同样计入有效使用。

## 4. 从贡献到维护：低门槛开始、按能力授权

建议路径：注册 → 完成一个小贡献 → 获得核验／感谢反馈 → 自愿申请具体板 → 平台核实工作样本与布点计划 → 有限试任 → 正式维护。

已熟悉现场的领队或维护者可凭工作样本直接申请，不要求机械完成次数任务。试任期、任务数量和考核窗口需用试点工作量确定，暂不承诺固定积分门槛。

| 角色表达 | 实际工作 | 回报 |
| --- | --- | --- |
| 山大王 | 布设／巡查关联山脚和山顶二维码、维护山顶板、处理反馈 | 山峰上的维护署名、贡献档案、平台物料工具、审核后的本板广告福利 |
| NPC 指路人 | 维护岔路来向与去向、核验变化、巡查物料 | 岔路署名、有效指路贡献、同样的本板广告福利 |
| 路段维护人（名称待测试） | 更新明确路段的方向、路面与障碍信息 | 路段署名、贡献记录、同样的本板广告福利 |
| 协作者／线上版主 | 只承担被授权的巡查、核验或留言管理任务 | 共同署名、贡献档案；不自动取得独立广告位 |

“创始维护者”可保留为历史荣誉；“当前维护人”显示任期／近期维护与负责范围。荣誉不自动带来永久控制权。板已有维护人时仍可申请协作，不能通过重复建点抢一块广告板。

布设要求记录合适位置、授权或管理方认可的依据、可追溯物料编号、最近巡查；未布设也可先做线上贡献，但不能展示“现场已布点”。不鼓励为保称号在恶劣条件下巡山。

维护状态建议：申请中 → 试任 → 生效 → 暂停／交接／撤销。退出需可行：保留合规历史贡献，撤销写权限与广告提交权，短链和公众内容继续可读。闭山、季节及客流影响应作为维护评价背景，不因客流少自动降级。

## 5. 权限模型：角色 + 资源范围 + 状态

后端判断一次动作时，至少检查：当前身份、能力、目标资源、有效任期／状态、所有权或利益冲突。前端隐藏按钮只是展示，不是鉴权。

建议数据对象（仅概念，字段需在实现前进入 API 与迁移设计）：

- `boards`：`peak | junction | segment`，绑定稳定地理对象；每对象每类型唯一。
- `memberships`：用户、board_id、角色／具体能力、状态、授权来源、起止时间。
- `contributions`：原始提交、观察时间与方向、核验状态、核验人、版本；贡献与管理权分开。
- `ad_slots`：每板唯一广告位；可有多个候选素材版本，但同一时刻只展示一个获准版本。
- `ad_reviews`：审核版本、人员／系统身份、结果、理由、有效期；提升首屏是独立决策。
- `audit_logs`：管理、授权、隐藏、核验、广告与交接的操作人、对象、前后值和原因。

同一座山维护权不隐含所有上山路段和邻近岔路的控制权；需要分别授予范围。多人维护共享该板一个广告位；由负责人协调提交，存在争议时交平台处理，不增广告槽。

禁止维护人硬删除批评广告主或自己的真实体验；违规可带理由隐藏，平台可复核恢复。名称、路径及难度有争议时保留版本和证据，不靠投票热度判真伪。

## 6. 广告福利的可执行方案

已确认底线：每板一个位置、维护人上传、系统审核、默认首屏外、优质可提升首屏。下面是实施建议。

### 流程

草稿 → 待审 → 通过／驳回 → 默认位展示 → 可申请或由系统发起首屏评估 → 首屏展示／退回默认位 → 到期／下架。修改已通过的广告，生成新版本重新审核，不能用改落地链接绕开审核。到期、撤销或投诉成立后立即停止对应版本展示。

上传者可撤回自己的素材，不能审批、置 `promoted=true`、修改审核结果或伪造曝光数据。账号有多个角色时仍禁止自审；与广告有关联的审核人应回避。

### “优质”不只等于点击率

| 维度 | 审核要看什么 |
| --- | --- |
| 真实性 | 主体、描述、价格／条件、服务地点和有效期是否可核对；审核不等于平台保证全部服务质量 |
| 场景相关 | 是否对当前地点与行程有用，是否需要用户额外判断不明风险 |
| 体验 | 文案清楚、加载轻、落地页一致，无强制下载、弹窗遮挡和误导按钮 |
| 社区反馈 | 可核对的有用反馈、投诉和处理记录；防自刷，不拿曝光量冒充满意度 |
| 时效 | 服务是否仍在、是否过期、季节及路况是否改变 |

建议冷启动由平台人工完成最终审核，系统做材料完整性与辅助检查；后续是否自动化由样本和成本决定。首屏提升记录理由和期限，可撤回，不保证永久位置，也不因维护等级自动获得。

### 首屏边界

默认位必须在目标手机尺寸的第一屏之外，靠实际布局验收；不能以“在留言区顶部”推定它一定在首屏外。提升后仍先显示地点身份、岔路方向／重要路况和主要打卡动作，再放清楚标注的广告，不覆盖或冒充这些信息。小屏无法兼容时回落默认位；该布局规则为提案，需原型验证。

空广告位不显示假广告，不拖慢核心内容。广告失败不影响打卡和指路。标注“广告／维护人推荐（广告）”，公开必要关联；提供独立投诉入口。

本轮不设计收费、收益分成或支付系统，不承诺收入。对于不投广告的公益维护人，署名、工具和社区认可应同样成立。

## 7. 防止激励走偏

| 可能的行为 | 提案约束 |
| --- | --- |
| 抢热门山头只为广告 | 范围申请、工作样本、试任、共同维护、可交接；不能只按先后顺序永久分配 |
| 刷扫码或低质留言升等级 | 不用次数自动授权；只认可可核验贡献，展示不同指标而非一个总分 |
| 为广告压制真实路况 | 独立投诉、审计、平台复核，广告审核与内容核验分权 |
| 重复创建山峰或路段增加广告位 | 对象去重、每板唯一槽、合并保留短链和历史 |
| 为排行榜冒险或公开不想公开的行踪 | 默认个人目标；公开排名自选；扫码计时与轨迹验证结果分开 |
| 维护工作太重、最后无人更新 | 一次小任务、协作分工、暂停交接、过期状态可见；先测每周实际负担 |

## 8. 待实现前的权限验收

1. 游客直接打开三类板都能看信息并打卡，注册失败不丢游客记录与草稿。
2. A 板维护人请求修改 B 板内容、广告、成员关系均被服务端拒绝。
3. 普通用户伪造角色或请求参数，不能获得核验、广告审核、提升或发布权限。
4. 自己或有关联者提交的广告不能自行审核；改素材后旧审核不适用于新版本。
5. 撤销或过期的维护身份立即失效；令牌仍有效也不能继续管理。
6. 私人记录不可通过公开流水、榜单、分享链接或 API 泄露。
7. 每板同一时刻只展示一个广告版本；默认在首屏外，提升可撤回并有日志。
8. 注册合并与维护交接并发重试均幂等；不能将一个游客身份的历史转给多个账号。
